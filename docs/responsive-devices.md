# 휴대폰·폴더블 화면 대응

## 범위와 구조

`src/styles/20-responsive-devices.css`는 `index.html`의 마지막 스타일시트로 로드한다. 기존 기능별 스타일과 저장·계산·내비게이션 동작은 유지하고, 좁은 화면에서 필요한 배치만 덮어쓴다. 모션 변경은 이번 범위에 포함하지 않는다.

- 기기 이름이나 사용자 에이전트가 아니라 브라우저가 제공하는 CSS 화면 폭·높이에 따라 배치한다. 아래 크기는 실제 제품 사양이 아니라 검증용 화면 크기다.
- 숫자와 차트 글자를 무조건 줄이거나 페이지 전체를 가로 스크롤시키지 않는다. 공모주 달력, 요약 차트·표, 패턴 히트맵 등 폭이 필요한 자료는 해당 영역 안에서 좌우로 움직인다.
- 모바일 내비게이션은 기존 767px 이하 기준을 유지한다. 768px 이상으로 바뀌면 `src/features/app/navigation.js`가 더보기 메뉴를 닫는 기준과 일치해야 한다.
- 뷰포트 메타 설정은 `viewport-fit=cover`를 사용하되 확대를 막지 않는다. 안전 영역 여백과 `dvh` 기반 높이 제한을 사용한다.
- 입력 글자 16px·높이 44px는 모바일 텍스트 입력의 목표다. 기존 ID 선택자와 브라우저별 날짜·파일 입력 스타일은 실제 화면에서 별도 확인한다.

## 추가 스타일의 분기점

| 조건 | 적용 의도 |
| --- | --- |
| 공통 | 좌우 안전 영역, 화면 높이에 맞는 대화상자 제한 |
| 폭 1100px 이하 | 공모주 달력과 상세를 세로 배치; 요약/전체 달력을 각각 700px/840px 최소 폭의 내부 스크롤로 유지 |
| 폭 1023px 이하 | 요약 분석과 공모주 누적 성과를 한 열로 배치; 예산 수식을 두 열로 정리; 넓은 요약 자료의 내부 스크롤 |
| 폭 767px 이하 | 기존 하단 메뉴 유지; 입력 접근성, 하단 안전 영역과 더보기 최대 높이 대응 |
| 폭 540px 이하 | 식비 예산 저장 버튼을 별도 줄로; 추천 예산의 설명과 금액을 세로 배치 |
| 폭 430px 이하 | 식비 예산 입력을 한 열로; 섹터 순위의 이름·금액·변화를 서로 다른 줄로 배치 |
| 높이 500px 이하 | 짧은 가로 화면과 키보드 노출 시 대화상자 공간 확보; 고정 헤더 높이 점유 완화 |

기존 기능별 분기점은 그대로 존재한다. 이 문서는 모든 스타일을 새 분기점으로 통일한다는 의미가 아니다. 새 파일의 로드 순서만으로 우선순위가 보장되지는 않으므로, 선택자 우선순위와 실제 계산된 스타일을 함께 확인한다.

식비 달력에는 키보드 초점을 받을 수 있는 `.summary-food-calendar-scroll` 영역을 추가했다. 날짜별 금액이 잘리지 않도록 내부 달력 최소 폭은 기본 630px, 화면 폭 680px 이하에서 560px다.

## 자동 확인

```sh
node --test tests/responsive-devices.test.cjs
```

테스트는 마지막 로드 순서, 확대 허용, JS/CSS 내비게이션 경계, 내부 스크롤 선언, 모바일 입력 규칙, 좁은 화면 배치, `dvh` 대화상자 제한을 확인한다. CSS 선언이 존재하는지 검사하는 구조 테스트다. 글자 잘림·실제 터치·키보드·노치·브라우저 CSS 우선순위를 입증하지 않는다.

## 확인한 실행 증거

Codex 내장 브라우저(IAB)에서 실제 개인정보 없이 합성 거래 18개를 UI로 입력해 확인했다.

- 주요 화면 13개를 `320×740`, `390×844`, `540×720`, `768×900`, `820×900`, `1024×768`, `844×390`, `1440×900`에서 확인했다.
- DOM 경계로 가로 넘침을 검사했다. 표·차트 등 의도된 내부 스크롤 영역은 전체 화면 넘침과 구분했다.
- Graphite와 Mineral 테마는 스크린샷으로 확인했다.

| 확인 경로 | 관찰 결과 |
| --- | --- |
| 768px 공모주 | 누적 성과 영역의 넘침을 발견해 한 열로 수정했다. 재확인한 유효 화면 폭 753px 안에서 패널 오른쪽 737px, 컨트롤 오른쪽 718px였다. |
| 320px 요약 | 요약 탭 6개에서 의도하지 않은 가로 넘침이 없었다. 식비 입력의 계산된 스타일은 글자 16px, 높이 44px, 폭 245px였다. |
| 390px 제품 입력 | 이름만 입력한 저장이 성공했다. 선택 입력 그룹 3개를 펼쳤을 때 입력 필드 넘침이 없었다. 가격 `1234567`은 `1,234,567`과 `123만 4,567원`으로 표시됐다. |
| 844×390 지출 구조 목표 대화상자 | 대화상자는 세로 8~382px 안에 표시됐다. 본문은 높이 178px에서 전체 내용 813px를 스크롤할 수 있었고, 하단 버튼이 보였다. |
| 320px 식비 달력 | 일별 금액 잘림을 발견해 내부 스크롤 영역을 추가했다. Graphite 테마 재확인 스크린샷에서 `13,500`, `98,765`가 잘림 없이 표시되고 달력 내부 가로 스크롤을 사용할 수 있었다. |
| 767×390 더보기·768px 전환 | 더보기는 위 24px~아래 326px에 표시됐다. 높이 300px에서 내용 587px를 내부 스크롤할 수 있었고, 768px로 전환하면 메뉴가 닫혔다. |

`boardMonth`, `summaryMobileViewSelect`의 모바일 글자 크기 우선순위 수정도 반영했다. 최종 새로고침 후 `boardMonth`의 계산된 글자 크기 16px와 이름만 입력해 저장한 소모품 기록의 유지를 재확인했다.

## 남은 검증 한계

구조 테스트 8개는 통과했다. 이는 CSS 선언을 확인하는 검사이며 새 식비 달력 영역의 실제 가독성까지 자동으로 입증하지 않는다. 아직 검증하지 않은 항목은 다음과 같다.

- 실제 휴대폰·Flip/Fold 하드웨어에서의 접힘·회전·터치 동작
- 운영체제 화면 키보드 노출 시 입력과 버튼 접근성
- 실제 노치·홈 표시줄의 안전 영역
- 200% 확대와 운영체제 글자 확대

현재 증거는 내장 브라우저의 화면 크기 변경 및 일부 입력·대화상자 경로에 한정한다. 모든 브라우저, 모든 저장·취소 경로, 실제 기기 접근성까지 통과했다는 뜻은 아니다.
