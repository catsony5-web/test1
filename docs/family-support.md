# 가족 지원 입금과 정산

가족 지원은 본인 명의로 대신 납부하는 대출·보험 등의 통과 자금입니다. 일반 수입 및 카드 결제의 N빵 정산과 구분합니다. 실제 금액과 보낸 사람은 UI에서 입력하며 소스나 테스트에 넣지 않습니다.

## 계산 기준

기존 `loanSupportSettlementBalance`는 개별 대출의 실제 상환 기록에 있는 가족 수령액을 입금월까지 더하고, 실제 상환월의 가족 원금·이자 부담액을 뺐습니다. 보험료, 미반영 예정 지출, 수동 조정은 포함하지 않았습니다. 기존 대출 화면에서는 이를 ‘이 대출의 기존 정산’으로 구분합니다.

새 가족 정산은 다음과 같습니다.

- 이번 달 필요액 = 해당 월 가족 대출 분담액 + 가족 부담 고정 지출. 같은 고정 지출·월에 실제 납부 기록이 있으면 실제 기록을 우선하며 예정액을 다시 더하지 않습니다.
- 이번 달 차액 = 정산 대상월이 해당 월인 입금 합계 − 필요액.
- 누적 차액 = 선택월까지의 대상월별 입금 합계 − 가족 부담 예정 합계 + 반영된 조정 합계. 부족·초과는 다음 달로 이월합니다.
- 상환 예정 보관액 = 누적 차액의 양수 부분. 입금을 기록했다는 이유만으로 중도상환 처리하지 않습니다.
- 실제 보관액 = 실제 입금일 기준 수령액 − 실제 가족 지출·반환·연결된 추가 상환액. 아직 출금하지 않은 정기 납부금도 포함하므로 상환 예정 보관액과 다를 수 있습니다.
- 내 가용액에는 가족 보관액을 더하지 않습니다. 가족 지출을 먼저 대신 낸 부족분과 그 부족분을 나중에 돌려받은 금액만 가용액을 조정합니다.

가족 입금은 일반 수입 및 저축률의 수입 분모에서 제외됩니다. 기존 수입에 대출 분담 일부만 연결돼 있다면 연결분만 제외하고, 가족 입금으로 전환하면 원래 입금 전체를 한 번만 제외합니다.

대출 상환 조정은 음수로 입력합니다. 연결하지 않은 기록은 예정으로 남고 잔액을 차감하지 않습니다. 실제 상환에 연결하면 실제 상환일 기준으로 한 번만 차감합니다. 정기 가족 부담분과 다른 연결 조정을 제외한 실제 원금 한도를 넘을 수 없습니다. 반환은 음수, 기타 조정은 양수·음수를 허용합니다.

## 입력 순서

1. **고정 지출 → 대출 등록**에서 대출과 가족 부담 원금·이자, 적용 시작월을 입력합니다. 납부 후에는 실제 상환 내역을 등록하거나 가져온 출금에 연결합니다.
2. **고정 지출 → 등록·수정**에서 보험료 등에 ‘가족 부담’을 켜고 부담액과 적용 시작월을 지정합니다. 변경한 월부터 새 이력을 적용하며 과거 실제 납부 스냅샷은 보존합니다.
3. **수입 입력 → 기록 목록 → 가족 지원 입금으로 전환**으로 기존 송금을 옮깁니다. 거래를 복제하지 않고 같은 ID·날짜·금액·메모를 유지합니다. 새 입금은 대시보드·소비 달력의 **가족 입금 추가**에서 기록합니다. 늦게 받은 이전 달 몫은 정산 대상월을 변경합니다.
4. **가족 정산 → 정산 조정·대출 상환**에서 초과금을 실제 사용했을 때 조정 기록과 실제 대출 상환을 연결합니다. 미사용 초과금에는 차감 조정을 만들 필요가 없습니다.
5. **설정/관리 → 가족 입금·송금인 설정**에서 송금인 키워드를 입력합니다. 이후 불러오는 이체입금의 송금인/내용에 키워드가 포함되면 가족 지원으로 분류합니다. 기존 기록과 사용자의 수동 분류는 자동으로 변경하지 않습니다.
6. **설정/관리 → 전체 백업**으로 저장합니다. 선택 백업에서는 원래 거래의 출처 항목, 고정 지출 원본, 가족 정산 조정, 설정을 함께 선택해야 관련 자료가 모두 포함됩니다.

## 저장과 복원

입금은 기존 거래 배열 안의 `incomeKind`, `incomeKindSource`, `familyTargetMonth`, `familySender`로 구분합니다. 원래 거래 ID와 출처별 백업 범위는 유지합니다. 일반 고정 지출은 `familyBurdenHistory`, 대출은 `loanSupportHistory`, 실제 지출은 `familyBurdenAmount`로 해당 시점의 부담을 보존합니다.

조정은 `familyAdjustments` 저장 키를 사용합니다. 기존 저장 어댑터와 일괄 저장, 스냅샷, JSON 백업·병합 경로를 사용하며 기존 데이터는 빈 배열·일반 수입 기본값으로 읽습니다. 같은 ID의 내용이 다른 조정과 부담 이력은 복원 화면에서 보관할 내용을 선택합니다.

검증은 가상 거래만 사용합니다. 분할 입금, 대상월 변경, 수입·소비 제외, 예정·실제 중복 방지, 기존 대출 연결, 조정과 실제 상환의 한 번 차감, 적용 이력, 저장 실패, 백업 왕복 잔액을 확인합니다.
