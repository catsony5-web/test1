# 유지보수 점검 기록

대상은 기존 정적 웹앱, 개발 도구·Git 설정·workflow, 별도 모바일/로컬 인증 개발본의 보안 경계입니다. 작업 시작 시 있던 모바일 연동·CSP·백업·SheetJS 변경은 보존했습니다. 1차 점검 후 승인된 v183 릴리스에서 저장 안정성 및 운영 배포 경계를 추가 개선했습니다. 실제 금융기관 연결은 변경하지 않습니다.

## 확인한 문제와 적용

| 확인한 문제 | 적용 |
| --- | --- |
| 루트 실행·검증 명령이 없고 README 배포 목록에 필수 assets·data가 빠짐 | Node 24 기준 package scripts, 아키텍처·협업·보안 문서, 정확한 배포 목록 |
| 개인 파일과 개발 소스가 함께 있는 루트를 범용 서버로 제공할 위험 | 공개 자산만 읽는 루프백 개발 서버, 동일 허용 목록의 dist 빌드 |
| 루트에 환경 파일·키·서명키·거래 이미지 제외 규칙 누락 | .gitignore에 유형·로컬 자료 폴더별 제외, 공개 일정만 명시적 JSON 예외 |
| 서비스워커가 다른 named cache도 조회 | 현재 앱 버전 캐시만 조회하도록 변경, API·인증 요청 제외 유지 |
| 요청마다 공개 파일 171개의 URL을 재생성 | 시작 시 공개 경로 Set을 한 번 구성 |
| 버전 쿼리 없는 precache 때문에 오프라인 초기화가 네트워크 실패를 먼저 기다림 | HTML과 정확히 같은 버전 URL을 precache하고 cache:sync·불일치 검사·다른 버전 혼입 차단 추가 |
| 약 952KB 엑셀 라이브러리가 head에서 HTML 파싱을 막음 | 하단 classic scripts의 첫 위치로 이동해 의존성 순서 유지 |
| 기존 테마 QA가 CACHE_PREFIX 템플릿을 버전 누락으로 오탐 | 실행된 APP_VERSION과 CACHE_NAME 의미 비교 |
| 기존 공개 일정 workflow의 Node 20·이동 가능한 action 태그·전체 쓰기 권한 | Node 24, 검증한 action SHA 고정, 갱신 job에만 쓰기 권한 |
| 일반 PR 검증 부재 | 읽기 전용 verify workflow와 PR 체크 템플릿 |

기능별 `src/features` 구조와 classic script/CSS 실행 순서는 유지했습니다. 협업 진입점은 [README](../README.md), 세부 수정 위치는 [아키텍처 지도](architecture.md), 변경 절차는 [CONTRIBUTING](../CONTRIBUTING.md)입니다.

## 검증

- 변경 전 루트 자동 테스트 150개 통과. 기존 QA 7개 중 1개는 테마 버전 문자열 오탐.
- 변경 후 `npm run verify`: JavaScript 97개 구문, 공개 자산 172개 연결, 루트 테스트 160개, 집중 QA 7개 통과.
- 추가 보안 검사는 합성 파일로 비공개 경로·경로 탈출·junction·임의 Host·POST 차단, 공개 산출물만 복사, 타 앱 캐시 조회 방지를 확인.
- 기존 모바일·로컬 서버 관련 표적 보안 테스트 51개 통과. 실제 OS 알림·Face ID·기관 인증 성공의 증거는 아님.
- 공개 파일 검사는 HTML, CSS 상대 자산, manifest 아이콘 및 서비스워커 목록 사이의 누락을 차단. 폴더 전체 복사 없이 명시된 파일만 빌드.
- `npm run build`로 공개 파일 172개 생성. `dev`의 무캐시 개발용 워커와 `preview`의 실제 배포 워커를 구분하는 테스트 통과.
- 서비스워커 설치 후 HTML이 요청하는 자산 80개를 네트워크 호출 0회로 제공하는 합성 오프라인 테스트 통과. 캐시되지 않은 새 버전은 구버전 파일로 대체하지 않음.
- 독립 로컬 주소의 빈 저장소에서 실제 브라우저 시작·현재 월·섹터 요약 전환 확인. 수정된 dist를 설치한 뒤 서버를 종료하고 새로고침해도 대시보드와 소비 달력이 정상 작동했으며 브라우저 오류·경고 로그 없음.

## v183 저장·갱신 및 배포 개선

- 읽기용 IndexedDB 연결을 트랜잭션 완료·중단 후 닫습니다. 합성 읽기 25회에서 연결 종료 0회였던 문제를 종료 25회로 검증했습니다.
- 저장 요청을 순서대로 처리하고, IndexedDB의 이전값 조회·수입 보호·직전 정상 사본·실제 값·저장 시각을 하나의 readwrite 트랜잭션으로 묶습니다. 일반 저장은 DB의 최신 설정을 유지하고 저장 시각만 갱신합니다.
- 엑셀은 거래·가져오기 정보를 함께 커밋한 뒤 화면 상태를 교체합니다. 메모·공개 일정 추가/변경도 저장 실패를 성공으로 표시하지 않습니다. 메모에는 실패 안내와 재시도를 제공하고 오래된 완료 응답을 무시합니다.
- 일반 저장 후 상태 갱신의 전체 스냅샷 읽기는 합성 검증에서 2회에서 0회로 감소했습니다. 실제 생성·사용자 새로고침 때만 목록을 조회합니다. 실제 사용자 데이터의 체감 속도 개선율을 측정한 결과는 아닙니다.
- 공개 일정은 브라우저 15초, 서비스워커 10초 제한시간을 적용하며 겹친 요청을 공유합니다. 실패·잘못된 응답에서 기존 정상 자료를 유지하고 캐시 대체를 표시합니다.
- KRX HTTP 403을 우회하지 않습니다. 공식 출처 수집 실패 시 기존 일정과 마지막 정상 확인일을 유지하고 갱신 실패 출처·시도 시각만 갱신합니다. 한 출처의 실패로 다른 출처가 조회되지 않는 문제는 제거했지만 불완전한 자료를 새 확정 일정으로 합치지 않습니다.
- Pages 배포는 `deploy-pages.yml`의 검증 → 공개 `dist` 빌드 → artifact 업로드 → 게시 흐름으로 제한합니다. 일정 갱신 workflow는 변경 커밋 후 같은 배포 workflow를 직접 호출합니다. 빌드에는 읽기 권한만, 게시 job에는 Pages/OIDC 권한을 부여합니다.
- `npm run verify`: JavaScript 102개 구문, 공개 자산 172개 연결, 자동 테스트 202개, QA 7개 통과. `npm run build`: 공개 파일 172개 생성. 별도 로컬 브라우저에서 합성 메모 자동 저장·새로고침 복원과 오류 로그 없음을 확인했습니다. 원격 CI·실제 운영 반영은 배포 실행 결과로 별도 확인합니다.

## v192 최소 유지보수 · 2026-09-21 · 로컬 검증

별도 릴리스 작업 사본에서 v191 대비 수정했습니다. 루트의 다른 작업·개인 데이터·저장 키는 변경하지 않았고, 이 단계에서는 운영 배포하지 않았습니다.

| 확인한 문제 | 수정 및 근거 |
| --- | --- |
| 잘못된 백업의 객체형 가맹점명·과도한 할부 개월이 먼저 저장된 뒤 분류를 중단시킴 | 복원 전 거래 필드 타입·유한 숫자·기존 2~60개월 할부 범위 검증. 오류 백업은 저장 0회·원본 유지, 정상 legacy 허용. 할부 확장에도 같은 범위 검사 |
| 정산금·할부·대출 변경이 저장 실패에도 메모리 변경/편집 종료 | 다음 상태를 별도 계산하고 성공 후 커밋. 기존 수동 저장 잠금 재사용. 대출 삭제는 달력 삭제의 명시적 성공 반환값 확인 |
| 한국 시간대에서 소모품 예상 재구매일이 하루 빠름 | addDays 입력·계산·출력을 UTC 달력 기준으로 통일. 서울·UTC·뉴욕 DST, 월말·연말·윤년 검사 |
| 공통 함수 4개를 보드에서 재정의하고 옛 대시보드 함수 27개가 남음 | 실제 사용 중인 공유 거래 UI는 보존하고 확인된 무호출/중복 정의만 삭제. 주석뿐인 charts.js와 HTML/SW 참조 제거. 전역 함수 중복 회귀 검사 추가 |
| 고정 지출·대출 처리에서 reclassify 뒤 다시 renderAll 실행 | 확정 중복 호출 5개 제거. 해당 작업당 전체 렌더 2회 → 1회 회귀 검사 |
| 951,904바이트 SheetJS를 초기 화면에서 동기 실행 | 첫 가져오기/내보내기 때 동일한 로컬 파일 로딩. 동시 요청 공유, 실패/30초 초과 후 재시도, 버튼 상태 복원. 오프라인 첫 사용용 precache 유지 |

검증 결과:

- `npm run verify`: JavaScript 132개 구문, 공개 자산 185개 연결, 자동 테스트 **464개**, 기존 QA **7개** 모두 통과.
- `npm run build`: 개인/개발 파일을 제외한 공개 파일 185개 생성. `git diff --check` 통과.
- 자동 검증은 저장 실패/예외/재시도/중복 제출, 잘못된 백업, 날짜 경계, 실제 SheetJS 왕복, 초기 HTML에서 파서 제외, 오프라인 파서 응답을 포함합니다.
- 별도 빈 로컬 저장소에서 합성 거래를 UI로 입력. 정산 10,000원과 3개월 할부 저장·새로고침 후 유지, 대시보드 월 배분 6,667원, 상세 내역·섹터 요약 표시 확인. 브라우저 오류/경고 없음.
- 초기 파서 script 0개 → 첫 내보내기 후 1개 확인. 실제 다운로드된 XLSX를 읽어 6개 시트와 합성 거래 30,000원을 확인. 브라우저 자동화의 다운로드 이벤트는 시간 초과했으나 다운로드 파일 자체로 완료를 검증했습니다.
- 대시보드 320px·768px 너비에서 문서 가로 넘침 없음. 앞선 v191의 전체 주요 화면 반응형 검사나 실제 폰/폴더블 실기기 검사를 대체하지 않습니다.
- 초기 HTML의 실행 대상 JS는 **69개 / 2,188,259바이트 → 68개 / 1,211,416바이트**. 압축 전 소스 기준 976,843바이트 감소이며 첫 실행의 실제 로딩 시간 개선율은 측정하지 않았습니다. 오프라인 설치는 여전히 SheetJS 본체를 백그라운드 캐시합니다.

아키텍처 지도에 엑셀 로더·금액 입력·빠른 입력의 소유 위치, 보드/상세 내역 공유 의존성과 저장 성공 후 반영 규칙을 추가했습니다. 폴더 전체 이동, 전체 CSS 삭제, 숨은 화면 렌더의 일괄 지연화는 하지 않았습니다. 마지막 항목은 엑셀 내보내기가 월별 DOM 표를 읽는 기존 의존성부터 분리해야 합니다.

## 남은 범위

- 웹 릴리스는 로컬 모바일·인증 서버 개발본을 포함하지 않습니다. 별도 작업의 원본은 보존합니다.
- 웹 저장소·내보내기 파일의 평문 특성은 유지됩니다. 앱 자체 암호화나 사용자 계정/서버 동기화는 이번 범위가 아닙니다.
- 같은 탭의 저장 순서와 한 트랜잭션 내 원자성은 검증했지만, 여러 탭에서 오래된 전체 거래 목록을 각각 편집하는 상황의 충돌 감지·자동 병합은 구현하지 않았습니다. 동시에 여러 탭에서 장부를 편집하지 마세요.
- `renderAll()`은 여러 화면을 함께 계산합니다. 지연 렌더링은 각 화면의 초기화 의존성과 대표 합성 데이터로 실측한 후 결정해야 합니다.
- 초기 캐시 171개 항목은 약 2.84MB입니다. HTML과 같은 쿼리 URL로 저장하여 동일 스크립트의 기본 URL/버전 URL 중복을 줄였습니다. 일반 네트워크에서 첫 화면 속도의 개선율을 측정해 보장한 결과는 아닙니다.
- Android/iOS 실제 기기, 금융기관 OAuth·조회, 공개 서버 침투 테스트는 수행하지 않았습니다.
- 로컬 검증 통과와 원격 CI 실행 성공은 별개입니다. workflow는 저장소에 반영된 뒤 실행됩니다.
