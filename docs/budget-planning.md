# 통합 소비 예산과 공개 아이디어 노트

## 위치와 계산 기준

- 대시보드는 예산 기능 추가 전 구성으로 유지한다.
- 월별 섹터 요약 → **예산 점검**: `예산 한눈에`의 주 요약·소비 표와 `주별 흐름`의 막대 그래프를 전환한다. 두 화면에서 같은 월 잔액·식비 잔액·추가 구매 가정 계산을 유지한다.
- 월 소비/식비/저축 목표는 `appSettings.spendingBudget.monthlyTargets[YYYY-MM]`에 저장한다. 직접 수정과 추천 적용 모두 선택한 월에만 적용한다. 저장 전에는 기존 공통 소비·식비 목표를 참고값으로 사용하고, 소비 한도가 없으면 임의 값을 만들지 않는다.
- 여유 = 월 한도 − 해당 월 기록 소비 − 미반영 고정 소비 − 미연결 예약. 미래 날짜 기록은 예정액으로 분리하지만 여유에서는 이미 차감한다.
- 소비에는 대출 이자와 미분류를 포함하고, 저축·대출 원금은 제외한다. 수입 기준 참고액은 별도 계산이며 소비 한도를 자동 변경하지 않는다.
- 이번 주는 월~일 중 해당 월에 속한 날짜만 집계한다. 주 목표는 월 한도를 날짜 수로 나눈 참고치다. 특별 소비를 반복 지출로 확대 추정하지 않는다.
- 실제 거래에 예약을 연결하면 예약 추가 차감은 중단한다. 실제 거래가 사라지면 다시 예약하고 경고한다. 한 거래에 여러 예약을 연결하면 확인 경고를 표시한다.
- 식비로 지정한 미연결 예약은 전체·식비 잔액에서 각각 한 번 차감한다. 연결 후에는 실제 거래의 금액·분류를 따른다. 기존 미지정 예약은 전체 예산에만 반영하며 사용자가 식비 여부를 정한다.
- 식비 잔액은 전체 잔액과 더하는 돈이 아니다. `전체 여유 안에서 식비로 더 쓸 수 있는 돈`은 두 잔액의 최솟값(최소 0원)이다. 주별 남음/초과도 월 잔액에 다시 가감하지 않는다.
- 예약 최대 500개. 새 예약을 조용히 버리지 않고 추가를 거절한다. 기존 자료는 자동 삭제하지 않는다.
- 이는 등록 자료 기준 소비 예산이며, 미입력 거래나 통장 잔액을 확인하는 기능이 아니다.

## 맞춤 추천 목표

- `사회초년·자취`, `사회초년·가족 동거`, `경력·저축 집중`, `수입 불규칙` 네 시작 템플릿을 제공한다. 필수 입력 없이 초안을 보여주되, 예시 금액은 실제 기록으로 표시하지 않는다.
- 값의 우선순위: 직접 입력(0 포함) → 선택 월 등록 기록 → 템플릿 예시. 없는 값은 `null`로 유지한다. 수입에는 유효한 등록 수입만 사용하며 취소/제외 수입은 제외한다. 일회성 입금이나 미입력 내역이 있을 수 있으므로 사용자가 유지 가능한 수입인지 확인한다.
- 고정 소비는 반영된 내역과 미반영 회차를 합산한다. 월세·관리비와 나머지 고정 소비를 분리하고 저축과 가족 부담 원금은 제외한다. 고정 식비는 고정 소비와 식비 한도에 속하는 같은 금액이다. 수입·고정비·원금 다시 불러오기는 해당 네 수기값만 명시적으로 초기화한다.
- 수입 기준 상한 = 기준 수입 − 저축 − 본인 원금 − 예비비. 고정 소비는 소비 목표 **안에** 포함되므로 다시 차감하지 않는다. 상한으로 고정 소비를 감당하지 못하면 부족액을 표시하고 추천 적용을 막는다.
- 템플릿의 저축·원금/월 예비비/식비 시작 비율은 각각 사회초년·자취 20/5/15%, 사회초년·가족 동거 25/5/12%, 경력 30/5/15%, 수입 불규칙 10/10/15%다. 이는 앱의 예시 규칙이며 통계 평균이나 공식 권장/최적 비율이 아니다. 고정 소비를 먼저 확보하고 제안 저축·예비비를 감당 가능한 범위로 줄인다. 직접 입력한 값은 조용히 줄이지 않고 부족액을 표시한다.
- 식비는 직접 목표 → 사용자가 완전성을 확인한 최근 완료 3개월 식비 중앙값 → 템플릿 비율 순서다. 예시 식비는 고정 식비 이상, 남은 소비 범위 이내로 조정한다. 수기 식비가 이 범위를 벗어나면 원값을 보존하고 적용을 막는다.
- 나이는 20대 초반(20~23), 중반(24~26), 후반(27~29) 및 이후 10년 단위로 선택한다. 예상 은퇴 나이는 65세를 수정 가능한 가정으로 사용한다. 연령 구간으로 소득 계획 기간의 범위를 표시하고, 나이로 월급을 추정하거나 은퇴까지의 예상 소득을 현재 한도에 더하지 않는다. 이전 `under40/over60` 값은 좁은 구간으로 자동 변환하지 않는다.
- 참고: [CFPB 예산 배분 안내](https://files.consumerfinance.gov/f/201603_cfpb_rules-to-live-by_my-spending-rule-to-live-by.pdf)는 개인 상황에 맞춘 규칙 조정을 권한다. 위 앱의 비율 전체가 CFPB 권장값은 아니다. [비상자금 안내](https://www.consumerfinance.gov/an-essential-guide-to-building-an-emergency-fund/)처럼 필요한 규모는 상황마다 다르며, 이 화면의 월 예비비는 장기 비상자금 잔액을 대신하지 않는다.
- 계산만으로 저장하지 않는다. 미확인 가정이 있으면 사용자의 확인 후에만 적용할 수 있다. 적용 시 수기 프로필(미입력은 null)과 해당 월 목표만 기존 설정 저장 경로에 원자적으로 저장한다. 해결된 템플릿 기본값을 수기 프로필로 저장하지 않는다. 입력 수정 후에는 이전 확인을 무효화하고 유효하지 않은 입력은 보존하며 적용을 막는다. 입력값을 외부 추천 API로 전송하지 않으며 기존 백업에 포함된다.
- 소비 패턴 상세도 저장된 월별 식비 목표를 사용한다. 이 화면에서 수정하면 해당 월만 갱신하며 다른 달과 공통 목표는 유지한다. 월별 목표가 없는 달만 기존 공통 목표를 사용한다. 소비 패턴 상세 잔액은 기록 기준이며, 약속·미반영 고정비까지 확보한 잔액은 예산 점검에서 확인한다.

## 공통 숫자 입력

`src/utils/numeric-input.js`와 `src/styles/18-numeric-input.css`를 사용한다. `data-number-kind`가 있는 입력만 개선하며 날짜·검색·식별자에는 적용하지 않는다. 종류는 `money`, `quantity`, `decimal`, `percent`, `duration`, 수량 단위는 `data-number-unit`으로 지정한다.

- 금액은 천 단위 쉼표와 정확한 한글 금액을 함께 표시한다. 예: `100,001` → `10만 1원`. 소수 수량·허용된 음수·비율은 각 입력의 원래 제약을 따른다.
- 읽기는 `NumericInput.read(input)`을 사용한다. 빈칸은 null, 숫자 오류는 NaN이며 0과 구별한다. min/max/step/required 검증을 유지하고, UI 포맷 문자열을 Number로 직접 변환해 저장하지 않는다.
- 동적 DOM은 명시 opt-in 필드만 관찰해 초기화한다. 프로그램에서 `.value`를 바꾼 뒤에는 `NumericInput.refresh(root)`, 저장 전에는 폼 검증을 실행한다. 브라우저 기본 프로토타입이나 전역 값 setter는 바꾸지 않는다.

## 고정 지출 자동 기록

정액 항목만 사용자가 자동 기록을 켤 수 있다. 앱 시작 및 관련 설정 저장 시 예정일 도래 여부를 확인하며, 앱이 닫힌 동안 백그라운드 은행 출금을 확인하지 않는다. 활성화/재개 전의 지난 회차는 새로 만들지 않는다. 변동액과 대출은 수동 확인한다.

불러온 출금과 금액 또는 이름이 겹치면 자동 기록을 보류한다. 이미 자동 기록한 뒤 파일을 불러온 경우에도 중복 후보를 안내한다. 사용자가 실제 내역을 골라 연결할 때에만 자동 생성 기록을 대체하고 원본 거래 ID·날짜·금액·분류를 보존한다. 고정 항목 편집은 지난 실제 기록을 다시 쓰지 않는다.

## 하루 1회 공개 자료

`자산 목표 → 부업·취미`에서 오늘/7일/30일/최근 1년 중 수집된 자료를 선택한다. 기본은 7일이다.

- 수집: `scripts/update-hobby-insights.mjs`
- 공개 데이터: `data/hobby-insights.json`
- 예약 실행: `.github/workflows/update-hobby-insights.yml`, 한국 시간 매일 07:30 (GitHub 실행 지연 가능)
- 출처: YouTube 공식 블로그, WordPress.com 공식 블로그, Shopify 공식 변경사항.
- 제목 키워드로 자료를 선별하고 주제별 활용 아이디어를 붙인다. 국내 바이럴 순위·판매량·수익 가능성 검증은 아니다. 원문 날짜/링크와 수집 시각을 표시한다.
- 개인 가계부 및 취미 입력을 수집기로 보내지 않는다. API 비밀키를 브라우저에 넣지 않는다.
- 수집 실패 시 마지막 정상 자료와 성공 시각을 보존하고 실패 시도를 따로 기록한다. 잘못된 응답, `private/no-store` 응답은 공개 오프라인 캐시에 저장하지 않는다.
- 이 워크플로가 운영 기본 브랜치에 반영되어야 자동 갱신이 시작된다. 로컬 구현만으로 운영 사이트의 예약 실행이 활성화되지는 않는다.

## 검증

계산 코어/실제 어댑터/저장 실패/중복 연결/회차 날짜/가져오기/피드 파서/서비스 워커 캐시 회귀 테스트를 `tests/`에 둔다. `npm test`, `npm run test:qa`, `npm run check`, `npm run build`를 실행한다. UI 검증은 개인 기록이 없는 별도 localhost origin의 합성 자료로 진행한다.
